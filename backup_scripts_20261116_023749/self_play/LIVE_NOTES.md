- Settings reset after a match or reload (user: role went back to Auto, then "all settings drop"): the likely cause is that Umbrella saves translated menu items by display text, which no longer matches the English options the script creates on load. `localization` now saves every dropdown (index), switch (0/1) and slider (number) itself in Config section `self_play_menu`, keyed as "<group>/<name>". It restores them when the menu is built and writes changes from OnUpdateEx. Lifecycle tests cover role, switch and slider surviving a reload. Deployed while the game was closed; takes effect on the next script load.
- Duplicate purchases (user log, Juggernaut): the bot started with a Quelling Blade, yet the build later showed "bfury > quelling_blade", so the bot's own inventory count missed the QB it had. Enigma's second Magic Wand recipe couldn't be traced: diagnostics were off that game. Fixes: (1) `shop.duplicate` checks before every purchase; if the game reports the item already in the hero's slots (NPC.GetItem with backpack and stash), or it's a recipe already held loose, the buy is skipped and logged. Stackable and consumable items are exempt. (2) New `[SelfPlay buy] <item> for <goal>; own: ...` line on every purchase, so the next duplicate is traceable. (3) Courier fix: with a full bag, the 3 s "give up" window started when the transfer was ordered, so any real flight was recalled and a component or recipe that would assemble never arrived. It now starts when the courier is within 400 of the hero, and recipes always count as deliverable. (4) `[SelfPlay build]` logs only when the build changes (it was spamming every refresh).
