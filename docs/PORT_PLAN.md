# PORT PLAN — поэтапный план порта Self Play

**Статус:** авторитетный план на 21.11.2026. Заменяет разрозненные `PLAN.md`, `EVENING_PLAN.md`,
`PARITY_MATRIX.md` в части *очерёдности и критериев приёмки*. Старые файлы остаются как история.

**Цель (из `PORT_BRIEF.md`):** запустить ОРИГИНАЛЬНЫЙ Lua «Self Play» на нашем лоадере
(`host16.dll`) с поведением, идентичным оригиналу Umbrella. Без Umbrella/Themida/HWID.
Финальная цель — 3 инстанса-фермы на одном хосте.

**Правило паритета (принято 18.11, см. `PARITY_MATRIX.md`):** идентичные входы/обработка,
возвраты (тип/структура/смысл), побочные эффекты, ошибки в тех же ситуациях, тайминги.
Заглушка ≠ реализация; заглушка допустима только как явный блокер с обоснованием.

## 0. Почему сейчас «фиксим одно — другое не так»

Self Play — это **слоёная система решений**. Каждый слой потребляет данные нижележащего.
Если нижний слой врёт, верхний ведёт себя «странно», и симптом виден именно наверху.

```
Слой 0  Субстрат        оффсеты сборки, список сущностей, игровые часы, тик-цикл
Слой 1  Значения API    Entity/NPC/Hero/Ability/Item геттеры (урон, скорость атаки,
                        дальность, состояния, модификаторы, позиции)
Слой 2  События         OnUnitAnimation(castpoint), OnProjectile(speed/isAttack),
                        OnEntityHurt(damage/source), OnNpcDying
Слой 3  Модель мира     helpers.scan → ctx.creeps/enemies/allies/towers/structures,
                        волны, LaneGroupsManager, видимость/дормантность
Слой 4  Ластхит         lastHit.plan: damage + ledger(события) + timing → candidates
Слой 5  Передвижение    helpers.move / navigation.goal / positioning / creep block /
                        lane anchor — цели приходят из ластхита и модели мира
Слой 6  Бой/касты       tactics.cast / fight_sim / awareness / spell_policy
Слой 7  Магазин         shop.run / courier / stash / inventory
Слой 8  Макро-решения   decide.run / strategy / выбор режима / win model / objectives
```

**Ключевая зависимость, которую мы упускали:** передвижение (слой 5) *потребляет* цели
ластхита (слой 4) и модель мира (слой 3). Пока ластхит/модель мира не в паритете, бот
«странно бегает» — это **не отдельный баг передвижения**, а следствие нижних слоёв.
Поэтому чинить передвижение отдельно, до паритета ластхита, — значит лечить симптом.

**Пример из 21.11:** `NPC.IsAttacking` считал атакой бег (1502=RUN). Это слой 1.
Следствия пошли вверх: creep block отбрасывал крипов (слой 5), `laneThreat.attacked`
всегда true (слой 6), ledger не наполнялся (слой 2→4), candidates=0 (слой 4).
Один фикс слоя 1 разблокировал сразу 4 слоя. Это и есть правильный порядок работы.

## 1. Анти-whack-a-mole протокол (обязателен для каждой задачи)

1. **Локализуй слой причины.** Поведение «странно» → спустись по цепочке и найди самый
   нижний слой, который врёт. Не патчи symptom на слое поведения.
2. **Докажи причину зондом.** Живой probe (`diag_*.lua` или временный лог в скрипте),
   который показывает конкретное неверное значение/событие. Без доказательства — не чиним.
3. **Чини в слое причины.** Одна функция/одно поле за раз, по правилу паритета.
4. **Перепроверь слой и всё выше.** После фикса прогони зонды этого слоя и зависимых
   верхних слоёв. Убедись, что симптом ушёл и не появился новый.
5. **Зафиксируй.** Запись в `KNOWN_ISSUES.md` (было/стало/доказательство) + хэш файла.
6. **Регрессия.** Перед любым live-запуском — `check_build.py` + регрессионный набор
   зондов (см. `TEST_PROTOCOL.md`). Не запускать бота «вслепую».

**Запрещено:** править оригинальные скрипты под `xYjGsPeqoWTEzbif\scripts\` как «фикс»
(они — эталон). Временная диагностика допустима только с бэкапом и последующим откатом;
постоянные изменения — только в `src/`. Единственное исключение — защитные fallback в
оригинале, если наша API не может дать контракт (помечать как блокер, согласовывать).

## 2. Фазы порта

Каждая фаза = **входные критерии → работы → выходные критерии (приёмка) → доказательства**.
Не переходить к следующей фазе, пока не закрыты выходные критерии текущей.
Фазы 0–3 — фундамент; 4–8 — поведение. Поведение проверяем только на стабильном фундаменте.

### Фаза 0 — Субстрат (СТАБИЛИЗИРОВАН, держать регрессию)
**Вход:** сборка Dota известна.
**Работы:**
- `check_build.py` зелёный (PUO RVA, dwLocalPlayerController, dwEntityList совпадают).
- Список сущностей стабилен (~5600, нет коллапса до 1–4). Фикс `ensureList` re-anchor.
- Тик-цикл: один Lua-state, корректная остановка (`stop.txt` + ожидание, см. протокол).
- Производительность тика: скрипт-часть < 250 мс в матче.
**Выход (приёмка):**
- `check_build.py` → «OK: build matches baseline».
- `[entity] iter build … n≈5600` стабильно, `NPCs.GetAll` не скачет 0↔148.
- `[perf] tick … script < 250ms` в течение матча (сейчас ~150–200 мс).
- Нет `runtime error` / `OnUpdate error` на протяжении ≥ 200 тиков.
**Доказательства:** host.log (строки perf/entity), `check_build.py` вывод.
**Статус 21.11:** ✅ достигнуто. Держать регрессионный зонд перед каждым запуском.

### Фаза 1 — Достоверность значений API
**Вход:** Фаза 0 закрыта.
**Уточнение 21.11 (живые данные):** API-поверхность Self Play по сути реализована —
в рантайме дёргаются лишь 2 заглушки вне скоупа (Panorama.GetPanelByName,
TempTrees.InRadius). «25 заглушек» из PARITY_MATRIX — скан ВСЕЙ папки scripts;
функции «батча 1» (Heroes.InRadius, IsPositionInRange, IsBuilding, Players.Get/Count…)
**Self Play не вызывает** (они из LDfarm/shaman_combo/…). Реализовывать их не нужно.
**Поэтому фаза 1 = проверка КОРРЕКТНОСТИ значений, а не закрытие заглушек.**
**Работы:**
- **Боевая математика** (кормит ластхит/бой): `GetTrueDamage/GetTrueMaximumDamage`,
  `GetAttackSpeed`, `GetSecondsPerAttack`, `GetAttackRange(+Bonus)`, `GetAttackAnimPoint`,
  `GetPhysicalArmorValue`, `GetArmorDamageMultiplier` — сверить с HUD/известными значениями.
- **Счёт игрока** `Player.GetTeamPlayer` (DataTeamPlayer_t) — сейчас мусор (AI-3);
  найти корректные оффсеты через player resource, сверить lastHits/denies/networth/gold/xp.
- **Состояния/модификаторы** — HasState/IsAttacking/GetModifiers исправлены 21.11,
  перепроверить на стабильном прогоне.
- Каждая функция: значение совпадает с игрой/HUD; граничные случаи (nil, мёртвый,
  нет маны); тип возврата как в оригинале.
**Выход (приёмка):**
- Зонд боевой математики: урон/скорость атаки/дальность героя и крипа совпадают с HUD.
- `[SelfPlay score]`: lastHits/denies/networth/gold/xp осмысленны (не мусор).
- Decision-critical геттеры возвращают корректный тип и значение.
**Доказательства:** зонд значений, `[SelfPlay score]`, запись в `API_PARITY_STATUS.md`.
**Статус 21.11:** 🟡 состояния/модификаторы исправлены; боевая математика и счёт
игрока — **следующий шаг** (проверка корректности).

### Фаза 2 — Достоверность событий
**Вход:** Фаза 1 (боевая математика и состояния достоверны).
**Работы:**
- `OnUnitAnimation`: `castpoint > 0` для атак, корректный `activity`, `lag_compensation_time`.
  Сейчас для атак крипов castpoint берётся из `unitStats` — проверить, что не 0.
- `OnProjectile`: `isAttack=true`, `moveSpeed>0`, корректные `source/target` (identity-тип!).
- `OnEntityHurt`: `damage>0`, атрибуция `source`, порядок hurt→dying.
- **Identity-совпадение:** `event.target` и `ctx.creeps[i]` должны быть одного типа
  (number vs cdata), иначе `==` в ledger молча не совпадает. Зонд `[hits]` это показывает.
- Ledger наполняется: `ctx.hits.events>0`, `cycles>0` во время боя на линии.
**Выход (приёмка):**
- `[hits] events=N cycles=M` с N,M>0 в бою; `confirmed` растёт при атаках героя.
- `castpoint` атак не 0; `observedPoint` героя соответствует его анимации.
- Типы identity в событиях и в ctx совпадают (зонд `tgtType`/`creepType`).
**Доказательства:** `[hits]`, `[ev] OnUnitAnimation/OnProjectile` строки.
**Статус 21.11:** 🟡 ledger наполнился (events=18, cycles=8) после фикса IsAttacking.
Нужно подтвердить castpoint атак и identity-типы на стабильном прогоне.

### Фаза 3 — Модель мира
**Вход:** Фазы 1–2.
**Работы:**
- `helpers.scan` наполняет `ctx.creeps/enemies/allies/towers/structures` корректно.
- Фильтры видимости: `IsWaitingToSpawn`, `IsDormant`, `IsVisible` не отсекают живых.
  (Сейчас `IsWaitingToSpawn` временно `false` — найти корректное поле/семантику.)
- Волны и `LaneGroupsManager`: правильная привязка к линии (lane id), состав групп.
- `ctx.waves[lane]`, `enemyWaves`, `rawLaneAnchor` дают осмысленные якоря.
**Выход (приёмка):**
- `[ctxdump]/[perfdbg]`: creeps/enemies/allies > 0 на линии, соответствуют видимому.
- Крипы корректно привязаны к линии бота; якорь линии не в чужой базе.
- Нет «пустого мира» при наличии волн.
**Доказательства:** `[perfdbg]`, `[ctxdump]`, LANE-дамп.
**Статус 21.11:** 🟡 мир наполняется (creeps=5–9, enemies=2–4). Якоря/привязка линии — проверить.

### Фаза 4 — Ластхит (ПЕРВОЕ ПОВЕДЕНЧЕСКОЕ ДОКАЗАТЕЛЬСТВО)
**Вход:** Фазы 0–3 закрыты (фундамент + события + мир достоверны).
**Работы:**
- `lastHit.plan` даёт `candidates>0` на линии; `window`/`timeline.choose` выбирают цель.
- Атака-ордера выдаются (`order=attack`), `attacks`/`confirmed` растут.
- Темп lastHits соответствует эталону (`REFERENCE_BEHAVIOR.md`).
**Выход (приёмка) — контрольные точки Treant role 4 lane 1:**
- К 1:00: ≥1 `order=attack`, `attacks>0`, `heroDamage>0`, `lastHits>=1`.
- К 5:00: `lastHits>=5`, `XP>=1500`, есть `cast=` (не только подхил).
- К 10:00: `lastHits>=10`, `XP>=6000`, `candidates>0`, attack-ордера присутствуют.
- `[SelfPlay score]` строки пишутся (трейс включён).
**Доказательства:** `self_play.log` + `parity_diff.py` против `REFERENCE_BEHAVIOR.md`.
**Статус 21.11:** 🟡 «ластхиты пошли» (наблюдение пользователя), но `candidates=0` в
замерах и темп не подтверждён. **Это текущий фокус.** Не переходить к передвижению,
пока ластхит не даст стабильные контрольные точки.

### Фаза 5 — Передвижение и позиционирование
**Вход:** Фаза 4 (ластхит даёт стабильные цели).
**Работы:**
- Creep block стартует вовремя (не на 55-й секунде), корректный `stage`/маршрут.
- Бот держится у своей волны, не уходит глубоко в вражескую территорию.
- `navigation.goal`/`coverAnchor`/`field.best` дают осмысленные точки.
- Распределение режимов/приказов приближается к эталону.
**Выход (приёмка):**
- Распределение `mode=`/`order=` близко к эталону (move/hold/cast/attack).
- Бот не «странно бегает»: стоит у волны, блокирует, отходит при угрозе.
- Позиция в `[SelfPlay] pos=` согласована с линией и волной.
**Доказательства:** трейс режимов, позиционные дампы, сравнение с эталоном.
**Статус 21.11:** 🔴 «странно бегает» — ожидаемое следствие незакрытых фаз 3–4.
Чинить **после** ластхита, не раньше.

**Мы на стыке фаз 1→4.** Фундамент (фаза 0) стабилизирован. API-поверхность Self Play
по сути реализована (лишь 2 заглушки вне скоупа). **Ближайшая задача — проверить

`check_build.py` → зонд субстрата (entity count, tick) → зонд боевой математики →
зонд событий/ledger → только затем бот. См. `TEST_PROTOCOL.md`.
